- **Design adjustment found while coding:** the design says the hinge rotation is 0 while the strip is drawn, but the rigid leaf ends at `turnedLeafAngle(j)` (a little under pi) so turned leaves stay above the cover and in order. ## Fix session after the two-zone drag fix: the cover follows the closing drag

- **Problem:** in the running app, dragging the left zone on page 1 closed the book only after release; the cover did not follow the cursor.
- **Chosen mapping:** the machine stays in `open` during the drag (`t = TOTAL`, so invariants I1 to I6 and the existing properties hold). The cover open fraction is derived from the drag progress (`coverScrub.ts`: `1 - progress`), and the driver multiplies the cover progress by it. On a release past 50 percent, `startClosingFromCover` scrubs the machine time inside the cover phase: `t` is set to the point where the eased cover progress equals the scrubbed fraction (inverse of the ease-in-out cubic), then the existing closing sequence runs, so there is no jump. Below 50 percent, or on Escape, the gesture progress settles back to 0 like a returned page.
- **Spec:** the design gained the subsection "Cover scrub" and Properties 33 to 36. The 50 percent rule, close waiting for idle pages and Escape routing came from the earlier design text and were reused unchanged.
- **Steering:** `tech.md` (no per-frame allocation: the new pure functions allocate nothing and the `useFrame` callback is unchanged; no new lights, shadows or timers; reduced motion respected), `structure.md` (all in `src/book`), `product.md` (a released short drag calmly returns the cover, nothing punishes).

Cursor rules (grab, grabbing) already existed in `index.html`. Timings and page text are unchanged.
- **Property tests:** Properties 33 to 36 (playbook P37 to P40, 200 runs each) in `coverScrub.test.ts`: monotonic angle, exact return to open, closing without a jump, angle range for NaN, infinities and out-of-range input.
